# REGLA_R5 — PERTENENCIA PROBADA POR CADENA DE CARPETA

**Sistema:** JULCON v13.1  
**Ámbito:** REGLA_BASE_CANONICA  
**Estado:** JULCON v13.1 / REGLA_BASE_CANONICA / NO_EMITIBLE POR SÍ SOLA  
**Tipo:** Regla operativa obligatoria de prueba de pertenencia documental.

---

## 1. Causa raíz

Durante un inventario se clasificó un archivo, `otra instalación-MMF-IE-PL-0101 Diagrama Unifilar`, como **gap del proyecto** confiando en el título/prefijo, sin probar su cadena de carpeta hasta una raíz del proyecto.

El archivo era de otro origen. El prefijo `otra instalación` ya había contaminado antes mediante una memoria otro centro de carga.

Este antecedente queda como caso de control: **falso gap es tan grave como falso hallazgo**.

---

## 2. Criterio rector

Ningún archivo se clasifica, cita, integra ni reporta, ni siquiera como gap del proyecto, hasta **PROBAR** que su carpeta padre asciende por cadena verificada hasta una raíz autorizada del proyecto.

Las raíces autorizadas son las que se declaren para el proyecto activo en su bootstrap de gobierno. No se usa ninguna raíz que no esté declarada y verificada para el proyecto en curso.

La pertenencia no se infiere por título, prefijo, nombre de subestación, disciplina aparente, similitud documental ni por sonar relacionado al proyecto.

---

## 3. Regla de prueba

1. La pertenencia se **PRUEBA** por cadena de `parentId` hasta una raíz autorizada del proyecto.
2. La pertenencia nunca se infiere del título, prefijo, nombre de SE o apariencia documental.
3. Toda búsqueda global de repositorio se considera **CONTAMINADA POR DEFECTO**, porque mezcla proyectos, clientes, bibliotecas de norma y documentos de contexto.
4. Cada resultado de búsqueda global nace como **FUENTE_NO_VERIFICADA** hasta probar su cadena de carpeta.
5. Sin cadena probada, el archivo no se usa para nada:
   - No se usa como fuente.
   - No se usa como faltante.
   - No se usa como referencia.
   - No se usa como evidencia.
   - No se reporta como gap.
6. Si la cadena de carpeta no puede probarse, por limitación de API o falta de confirmación de origen, el archivo permanece **FUENTE_NO_VERIFICADA**.
7. Un archivo debe excluirse si su cadena asciende a otro proyecto o cliente, por ejemplo otro cliente, otro centro de carga/otra instalación, otro cliente, bibliotecas ajenas o normas de otro contexto no aplicable.

---

## 4. Prohibiciones

- Prohibido clasificar un archivo como del proyecto por su título o prefijo.
- Prohibido clasificar un archivo como faltante del proyecto sin cadena de carpeta probada.
- Prohibido reportar un gap basado en un archivo cuya cadena de carpeta no se probó.
- Prohibido tratar la búsqueda global como inventario.
- El inventario se hace navegando la jerarquía desde las raíces autorizadas del proyecto hacia abajo.

---

## 5. Método correcto de inventario

El inventario se ejecuta navegando desde las raíces autorizadas del proyecto hacia abajo:

1. Confirmar raíz autorizada.
2. Enumerar carpetas hijas.
3. Enumerar subcarpetas.
4. Enumerar archivos.
5. Registrar cadena de carpeta / `parentId`.
6. Solo después clasificar frente, disciplina, rol y estado de lectura.

La búsqueda por título puede usarse solo como herramienta auxiliar de localización, nunca como prueba de pertenencia ni como inventario.

---

## 6. Relación con reglas de cobertura

- **R2** = pertenencia: pregunta si la fuente pertenece al proyecto.
- **R5** = método de prueba: prueba por cadena de carpeta, no por título.
- **R4** = universo al arranque: se enumera desde las raíces, no por búsqueda.
- **R3** = barrido antes de cierre: verifica que todo el universo fue cubierto antes de declarar cierre.

Síntesis operativa:

- **R5 es el método de prueba que hace ejecutables a R2 y R4.**

---

## 7. Estado por defecto

Todo archivo sin cadena de carpeta probada queda por defecto:

**FUENTE_NO_VERIFICADA / NO_EMITIBLE.**
